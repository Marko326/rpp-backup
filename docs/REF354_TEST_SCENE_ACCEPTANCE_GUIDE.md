# REF-354｜测试模式逐场操作与可见验收标准（复核修正版）

> 适用于本次“复核修正版” REF-354 开发候选，不适用于先前没有修复测试夹具的 REF-354 ZIP。
> 测试菜单和夹具只属于 `BATTLE_TEST_BUILD`：必须构建 TEST Red 或 TEST Blue；正式 ROM 不显示 Pokey 的测试菜单。使用独立测试 SAV，因为选场景会重置当前队伍。

## 进入方法

1. 在 TEST Red / TEST Blue 中前往 **玉虹大厦 1F（Celadon Mansion 1F）**，找 **Pokey** 对话。
2. 依次选 `SELECT TEST` → `TRANSFORM TEST`。进入后光标默认在 `PAGE` 行；停在 `PAGE` 行按**右方向键**翻到第8页或第9页；到目标场景，按上方向键移到对应行，再按 **A** 启动；B 返回上一级。
3. 第8页：22、23、24；第9页：25、26、27。每次测试前重进菜单、重新选择场景，勿沿用前一次战斗的 HP/状态。
4. 只记录**第一回合、首次命中**的情况；Spark 的麻痹随机、暴击、命中随机会影响后续比较。推荐拍一段从进菜单、选场景、首回合伤害到下回合开始的录像。

## 重要设计：把“威力65”和“异常威力”区分出来

复核版将四个 Spark 测试中的攻击方能力设为 **170**，受击方对应的防御或 Special 设为 **100**，双方受击目标初始 **HP 120/120**，等级50，同为普通属性卡比兽（Spark 电属性对普通属性中性，无 STAB）。物理例：Attack170 / Special65；特殊例：Attack65 / Special170。按项目当前伤害算法估算，**无暴击、无其他临时变化、命中时约扣 42～50 HP**，剩余约70～78 HP；个别随机边界以 ROM 实测为准，不宜把这一估算当作精确汇编/设备证明。

旧版错误会把 D=65 覆盖为 WRAM 地址的高字节，玩家侧 `wBattleMonSpecial≈$D02B` → `$D0`(208)，敌方侧 `wEnemyMonSpecial≈$CFFC` → `$CF`(207)；在同一夹具中理论伤害远高于正常值，**很可能首击直接 KO 120 HP**。这才是这组测试需要直观看出来的**修复前后差异**。注意旧 REF-353 没有这些新增夹具，不是说旧版能够直接选择22～25场景比较。

| 场景 / 页 | 开始前应看到 | 你的操作 | 正确预期 | 一眼可见的失败迹象 |
|---|---|---|---|---|
| **22 P-SPARK-P** /8 | 玩家卡比兽首招 Spark；对手卡比兽只会 Splash；玩家 Attack170 > Special65 | 第1回合选首招 **Spark** | FIGHT 菜单预测 **Physical**；正常非暴击命中后敌方仍存活，HP条剩约六成；Spark 正常电光动画 | 没有 Spark、显示 Special，或敌方被普通首击秒杀；再排除暴击/其他变数 |

### 怎么让动画对照更明显？

- 测完 26，再在普通战斗找会使用 Spark 的宝可梦或重开22，观察真正 Spark 的闪电。**26 应该没有这套 Spark 闪电**。
- 测完 27，对照普通 Comet Punch 的多拳动作。**27 只应按 Tackle 兼容动作播放**。
- 当前游戏内只提供 EXT13、EXT04 两个代表性碰撞的操作测试。EXT06、07、08、09、17、27 共六个其他碰撞受统一源码分流保护与静态测试检查，**不能说已逐个实机测过**。

## 判定范围与异常时应怎样记录

- **通过一项 Spark 的最低条件**：场景的首招/敌方出招正确；分类菜单在玩家场景正确；无暴击普通首击未 KO，敌方出招时玩家血量明显仍大于0。建议同时记录一次可见的数值 HP。
- **不能只看 Spark 动画断定威力修好**；动画与威力是两条独立的代码路径。
- **普通首击秒杀**通常是异常，但必须先排除会心、目标属性/等级不符、或测试场景没有正确初始化等情况；若明显不符，请保留从测试菜单开始的录像，不要直接给开发功能判失败。
- **本版不验收**烧伤分类、Attack=Special 平局、Metronome/Mirror Move、Counter/Sucker Punch、所有8个扩展碰撞的设备表现，这些仍需后续专项测试。
- 本轮仅有源码/静态回归；没有在本环境运行 RGBDS 编译、链接 ROM 或生成新 MAP，四种构建与实际扣血必须由本机验证。
