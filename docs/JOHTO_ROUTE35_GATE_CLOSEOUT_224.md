# ILEX-5.62.224｜35号道路—满金市门房正式收口

## 版本与范围

**一个可玩版本：ILEX-5.62.224。** `.224` 期间初次门房接入、南边界与到达步进修正、ROM0 止血、门毯碰撞时序改正、强制合同加固都是同一版的候选迭代。版本不升 `.225`，不会为一次失败候选虚增一个游戏版本。

本轮在 `.223` 主线基础上仅正式接入 Route35↔GoldenrodCity 中间的 Route35GoldenrodGate（Gold 既有两侧地形）。没有重新移植 Route35/36，也不扩展其它街口、自然公园剧情或 NPC。

## 本轮失败史必须保留

1. 初版只校验 Warp 数量与目标，遗漏 Route35 南边缘外景，出现连续树林；从 Gate 南口到达满金市缺 `D_DOWN`。早期 586 项 PASS 不等于行为正确。
2. ROM0 原本仅数十字节余量，新增调用导致 `Home Copy Data` 无法安放；后续将边界刷新合并为 ROMX dispatcher 减少 ROM0 调用开销。用户回传的 MAP 表明**一次**构建已成功链接、ROM0 总使用 `$3fe0`，仍非常紧张。
3. 北侧门口误将 `STEP_ON` 当作必然正确，导致玩家不能先站在门毯上左右走；最终 Route35 外侧使用 `COLLISION_ONLY`，与 `.215` 桐树林北门房已接受的踏格入口并不相同。到达后的 `D_DOWN` 属独立规则。
4. 旧脚本检查字段和字符串但未执行真实方向分支；增强工具对已开放四座门房、Gold 原版几何与实际图块、原生 Warp 路由、落点是否撞墙、双地图加载路径与错误注入强制 fail-closed。

## 确认的最终行为

- Route35 外侧 `(9,33)/(10,33)`：可以踩在门毯上停下、左右换位置；再次朝下碰撞门口才传送。
- Gate 北口 `(4/5,0)` 到达后向下自动走 1 格，Gate 南口 `(4/5,7)` **不**自动多走。
- Gate 南口经单格合流至满金 `(19,1)` 后向下自动走；从 Gate 北口回 Route35 外侧不追加向上步进。
- 两条加载路径的室外显示边界与屋顶更新保持；门房内图块及调色不与 Kanto 旧 Gate 混用。

## 验收与证据边界

- 用户明确反馈最新版本已手机测试并无发现问题；`224定稿.mp4` 是约 25.6 秒的最终可见证据，显示城市、门房和 Route35 的往返和外观。不能将它解释为所有 Lane/按键组合、全部旧地图/存档逐帧自动测试完成。
- 本轮基于最终候选原样重新运行：`617 tests / OK`；`tools/johto_gatehouse_behavior_audit.py` 独立 `PASS`（需要 `JOHTO_GOLD_SOURCE` 与 `JOHTO_GOLD_ROOT` 指向完整原版）。20 项门房加固专项负向用例强制在统一门禁中登记。
- 用户提供的 `rppred(1).map` 表示一次成功链接、ROM0 用了 `$3fe0`，尚无修改门房工具状态后的新 MAP。工具与文档收口不更改游戏 ROM 指令。
- 统一 Gold 审计的 `SafariZoneBeta` 已知图形窗口错误仍存在并被用户允许独立搁置；**没有屏蔽门禁，也不宣称全量发布审计全绿**。

## 提交建议与下一阶段

保持一个游戏版本 `.224`；如 `.224` 尚未提交，建议两笔 Git 提交：

1. `fix(johto): 完成 35号道路—满金市双向门房与 .224 实机纠错`：仅本阶段最终 ROM 相关 ASM、地图、图块、Warp、边界缓冲和版本 `.224`；包含历史上纠错后的最终可玩结果。
2. `test(tool): 强制 Gold 门房执行合同并完成 .224 收口`：工具、测试、`johto_door_contracts.json`、TODO、踩坑、专项收口文档和提交说明；保留早期失败原因，绝不把 Python PASS 冒充全 ROM 验收。
