# 城都室外地图｜临时封路与必须保留障碍登记（P2-1 MAP-5.62.138 清理更新）

> **用途**：每次把下一张室外地图接入 RPP 之前、之后，都要核对这张表。此表用来避免把旧的临时封路留下，也避免误删 Gold 原版树林、RPP 跳崖碰撞或必要边界。当前 .138 地图补丁已包含定点清树；本轮文档清理不修改地图字节、不编译 ROM、不替代完整游戏回归。
>
> **基线**：用户提供的 `MAP-5.62.138.patch`（从已提交 `.136` 基线导出）及此前 Gold 参考数据。CSV 同目录，可作为后续逐项清理检查表。

## 分类与清理规则

| 分类 | 例子 | 是否能清 |
|---|---|---|
| `TEMP_TERRAIN` | 未开放出口前特意放的路障树、岩石、围栏等地形块 | **只有登记的前置地图已接通，并完成定点恢复/连接验证，才清** |
| `TEMP_EDGE_GUARD` | 在 `home/overworld.asm` 暂时限制走出未开放地图边缘 | 对应相邻地图上线后定向调整，绝不整段删掉 |
| `TEMP_NOTICE` | 指示“门暂未开放”的临时路牌/对白 | 与具体门、室内或边界任务绑定，不能随便先删 |
| `TEMP_TEST_NPCS` | 为 NPC 图形排错临时摆放的人物 | 另走 NPC 专项，不跟地形一起自动删 |
| `ORIGINAL_OBSTACLE` | Gold 原版森林、河流、岩壁、跳崖、砍树点 | **不自动删除**；原版确需技能/剧情的保留机制或单独登记 |
| `ENGINE_REQUIRED` / `FUNCTIONAL_MAP_EDIT` | RPP 跳崖区块变体、接通地图的地形修正 | **必须保留**；不可直接恢复 Gold 版造成回归 |
| `SAFETY_EDGE_GUARD` / `DEFERRED_INDOORS` | 无邻接地图的外边界、尚未制作的室内入口 | 暂保留，待对应阶段独立验收 |
| `UNKNOWN` | 发现与 Gold 不同但来源不清的块、对象或碰撞 | **禁止自动清理**，先查提交、地图作用及运行时行为 |

## 今后每接一张室外地图，必须执行的检查（不得省略）

1. **接图前**：列出新图与每张相邻已接入地图的方向、宽度/高度、边界通道和原版 Gold `*.blk` 来源；如共享布局，按 `data/maps/blocks.asm` 真正引用定位。
2. **逐项登记**：比较 Gold 与 RPP 的 `.blk`、地图事件对象、Warp、入口封路 NPC、地图头连接以及 `home/overworld.asm` 的代码边界；每个差异要有 `id / 分类 / 位置 / 原值 / 现值 / 设置原因 / 解除条件 / 状态 / 验证`。
3. **先确认，后修改**：只处理状态为 `CONFIRMED_REMOVE` 且解除条件已满足的定点项；`PRESERVE`、`UNKNOWN`、仍依赖未做地图/室内的项不可一起删。
4. **最小更改**：只改对应 `.blk` 的特定坐标或对应的代码分支；禁止“全图替换树块”，禁止直接用 Gold 整张地图覆盖已经改造的 RPP 跳崖区块。
5. **检查可达性**：静态核对入口前后一格的碰撞、连通方向、连接高度和回退路径；在游戏内验证双向通行、边缘安全、路牌、跳崖、Continue、渡轮和关都回归。
6. **提交前收口**：更新 CSV 中 `status / verification` 和本 Markdown；`TODO.md` 与 `RPP_DEVELOPMENT_PITFALLS.md` 写结论，补丁只纳入必要内容。未经运行确认，不把静态结果标为“玩家已通过”。
