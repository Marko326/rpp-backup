# Route33 第2阶段：Gold 逐象限碰撞及单向跳崖安全模型（R33C-5.62.190）

**重要：本补丁不可进行 Route33 手机测试。** 游戏显示版本仍为 `DIG-5.62.188`，未注册 Route33 地图、运行时图块集/碰撞、连接、音乐或 Warp。地图的三侧封锁没有解除。

## 数据与结果

严格读取 Gold `maps/Route33.blk`、`data/tilesets/johto_modern_metatiles.bin` 和 `data/tilesets/johto_modern_collision.asm`，将原版 10×9 个 32×32 区块转换为 **20×18 个 16×16 碰撞格**。只在 `tools/johto_route33_staging/geometry190/` 产生离线数据：

- `Route33.blocked_mask.bin`：**18 行 × 3 字节 = 54 字节**，低位对应 X 从小到大；1 表示当前格不允许正常步入，0 表示许可正常脚步（仍需满足最终运行时其它碰撞与状态规则）。实际 182 格阻挡、178 格通行。
- `Route33.geometry.json`：记录 Gold 9 类碰撞角色、图像共用角色、原始 SHA-256、洞口封锁及 **7 个定向跳崖操作**；跳崖向左 3 次、向下 4 次，其中 `(9,12)` 允许两个方向。每个记录验证相邻阻挡格、落点和进一步一步位置。
- 图像 ID `$3C` 同时代表 FLOOR、WALL 和 UP_WALL，`$05` 同时代表 FLOOR 及跳崖，`$3E` 同时代表 WALL 和 HEADBUTT_TREE。不能从全局 `tilecoll` 白名单推断 16×16 语义，也不能凭图像 ID 自行增加任意跳崖；Gold 的 HOP_DOWN_LEFT 必须展开为 2 个方向，并做落点防越界检查。
- Route33 洞口 `(11,9)` 仍明确标为禁止正常步入，西侧桧皮镇、北接 Route32 的双向口仍**不开放**。联合洞穴当前 `.188` Dig／逃洞绳仍固定返回 Route32 洞口。

## 运行时仍需处理（当前未实现）

1. 本期**没有复制/修改** RPP `gfx/tilesets/*` 或 `gfx/blocksets/*`。虽然 Gold `JOHTO_MODERN` 的源图像有 96 个 8×8 图块，但 96 个 ID 都可能被 Gold 区块集引用。不能想当然把 `$60/$61` 加作图像副本：现有 RPP 的图块与 CGB 调色加载窗口为 96 个图块；超窗口图块必须先审核实际 VRAM 与调色加载逻辑。优先考虑坐标掩码与小型定向跳崖白名单，而不滥加全局 passable 图块。
2. 逐个查明 `wXCoord/wYCoord` 与正前方目标格的偏移、跨地图边缘、碰撞携带标志，再将 54 字节位置掩码真正挂入 Route33 运行时。此次 **54 字节掩码只是复核数据，不是引擎已经执行的碰撞逻辑**。
3. 注册完整地图身份、独立 `JOHTO_MODERN` 图像/区块/调色/音乐/骑行/普通 Town Map 当前位置与音效；严格验证 `$FC` 句柄下本地 ID，不破坏既有 9 张地图的 ID。
4. Route32 南侧仅在 Route33 北侧安全连通、边缘和加载顺序经过审查后**定点**解封；桧皮镇及联合洞穴第二出口继续封闭。开放后者之前必须单独升级 Dig／逃洞绳的动态入口保存机制。
5. 用户自行 Termux 编译/链接且提供 MAP 与实机结果后，才能标注 `BUILD_PASS` / `PHONE_ACCEPTED`。本期仅 Gold 静态对照，不证明 ROM Bank 可装下新内容。
