## 为什么之前屋顶会错、怎样防复发

地图 `.blk`/tilepal 转换结果本身与原始 Gold 数据一致；错误在后续接入时仅把城镇当成调色单位，并忽略 Gold **mapgroup 同时决定屋顶颜色与图案**，P19C 只对满金市 local ID 处理，导致 Route34 又恢复绿色。早期 P19C 包还错误使用已经被热修的开发树充当原始 `.216` 做自证补丁；必须从真正原始项目和确切前置补丁重建基线。

本次新增 `tools/johto_roof_reference_audit.py`，不再手动维护一份固定的 16 张地图候选表，而是动态读取 RPP `tools/johto_native_maps.json` 的所有本地 ID 和实际 `data/mapHeaders/*.asm` tileset，并以 Gold 地图组指针、地图所属组、`roofs.asm` 图案分组、`roofs.pal` RGB5 为信任源：

1. 对已注册城都 **JOHTO/JOHTO_MODERN 室外**，逐一比对 RPP 调色表与图形表的分组，强制长度与 `NUM_JOHTO_MAPS` 一致。新增地图即使漏掉屋顶表也会报错。
2. 核对所有生效组的 RGB5 必须等于 Gold 白天数值；对原版 `new_bark/violet/azalea/goldenrod` 9 tile 图像按真实像素编码做二进制逐字节比较；未知组无对应艺术资产时拒绝，而不是使用默认绿色。
3. 核对仅城都本地地图参与替换、室内不误涂色、完整载图和边缘无缝连接的图形钩子存在；和 `johto_map_release_audit.py` 集成，要求负向测试名称真实被运行。
4. `tools/johto_rpp_pipeline.py` 的每张新室外地图离线 `onboarding` 检查清单里新增 `roof_mapgroup_gold_reference`，**只提示必须检查，不等于自动批准/自动接入**。原有碰撞、门房、Fly、自行车、Surf 等独立关卡不变。

未来每做一座城市或一条道路，必须先用原版 Gold 确认 mapgroup，再登记 RPP local ID、屋顶 RGB/9 tile 与双加载钩子。非室外图不启用屋顶染色，不得凭截图“近似黄色”手调原始数值。新地图未经本审计不得声称外观完成。
