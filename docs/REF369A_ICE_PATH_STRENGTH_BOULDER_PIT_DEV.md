# REF-369A@｜冰之通路 B1F 怪力推石与石块落洞开发说明

> **历史开发说明，已被 REF-369B 第一阶段纠正。** 本文中“D855 bits 0–3 是未使用尾部事件位”的说法是错误的：D855 bits 0–7 全部属于 Johto Fly／Articuno 事件。REF-369A 的 `EVENT_9D7 / 8 + 1` 计算把 D854 错误偏移到了 D855。当前权威分配、一次性迁移及旧存档限制见 `docs/REF369B_SAVE_FLAG_ISOLATION_STAGE1.md`。不要再按本文旧分配制作新补丁。

## 基线与范围

- 当前 Git 分支 `常规功能备份`，本次原始项目 ZIP 经导出信息确认为干净正式 HEAD `935b3fa738dce42f22768e94c92c920bb5b86d89`，游戏版本 `REF-368@`。本轮开发标记 `REF-369A@`；尚未正式提交。
- 本轮不改 BANK0、不扩 WRAM/存档尺寸、不新增地图，不改变 70 张活动地图、188 条方向 Warp。地图和动画沿用 REF-368 已接受的正常状态。
- 四块 B1F 石头在 Gold 原版位置 `(11,7)`、`(7,8)`、`(8,9)`、`(17,7)` 由不可移动对象改为 `BOULDER_MOVEMENT_BYTE_2`，复用游戏现有 Strength A 键入口与推石动画。
- 复用原版四处 PIT `(11,2)`、`(4,7)`、`(5,12)`、`(12,13)`。每次移动后，使用系统 `wFlags_0xcd60` 完成标志和 `CheckBoulderCoords` 对真实动态位置比对；不凭石头初始位置判断。

## 推石、保存与下层

- 目标位置仅可为 Gold FLOOR／ICE／未填 PIT。WALL、楼梯、原版方向墙、地图外和已填 PIT 禁止继续推动。沿用 Bank3 已有 sprite-to-sprite 检测，碰撞结果以 Carry 跨 Bank 返回，不增加 Bank3 字节，并维持旧例程 A=`$ff` 阻挡／A=`0` 通行的接口。
- 源头石头消失写入已有 `wEventFlags` 字节 D853 的 4–7 位，落点占据写入保留的 D855 字节 0–3 位，两组分别按“哪一块石头、哪一个洞”记录，允许互换洞口落下并随存档保存；不覆盖原有冰洞 Dig/逃洞绳位 D853 的 2–3 位或 Dark Cave 位 D854 的 6–7 位。
- 落洞后源图石头从显示和碰撞坐标中移除；下层 B2F 卡吉侧 `(11,3)`、`(4,7)`、`(3,12)`、`(12,13)` 仅在相应 PIT 被填满后显示固定石头。未到达的下层石头同样清除绘制和碰撞坐标，避免隐形墙；下层物体不允许再用 Strength 推走。
- 复用现有 Gold `GSSFX_BURNED_TOWER_STRENGTH` 音效 ID，而非不存在的 `SFX_STRENGTH` 常量；保持原本的自行车、冰面滑行、步行动画、楼梯与跳崖处理不变。
- 现有项目中的 Strength 公共入口仍沿用原工程的彩虹徽章要求（不是自动切换为 Gold 的满金道馆徽章要求）。这是全项目既有逻辑，本轮未改。
