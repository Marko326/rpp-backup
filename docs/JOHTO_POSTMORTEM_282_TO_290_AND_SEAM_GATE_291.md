# TOOL-5.62.291 | 282→290故障复盘与新的连接准入门禁

> 这是纯离线工具补丁，不改变FIX-5.62.290的ROM、Map、Bank、音乐或存档；保留 TEST-231。并非新ROM或实机验收。

## 先回答审计覆盖问题

`.290` 修好了 **Route35 NORTH → Route36** 的13列屏幕预览，`johto_route36_seam_audit_289.py` 已直接检查10/12/14列、错源行、错目标列并有故障注入。但这是指定地图的精确合同，不是自动对所有未来新道路验证所有角落的渲染模拟。Gold源的142条有向连接只检查拓扑，不是WRAM屏幕预览证明。

## 新的强制门禁（本次实现）

- 新增 `tools/johto_active_seam_coverage_gate_291.py`，从**实际** `JohtoPilotSourceConnections` 扫描全部当前已登记直接连接，而不是只遍历事先写在旧测试里的样本。
- 任何没有完成独立审查登记的新有向连接都使总审计失败；任何缺少返程方向的连接也失败。
- 每张已登记地图从当前活动地图宽度中识别 `NORTH/SOUTH` 的“窄图接宽图”风险；**新的风险连接没有可视缓冲审查合同就立即失败**。当前五个风险连接均有单独核对（Route30北→Route31、Route30南→吉花、Route32北→桔梗、Route34北→满金、Route35北→Route36）。这些连接的Gold偏移不同，不能无脑统一“+3列”：例如Route30北端Gold起始列10、南端起始列5、Route35北端需13列。
- 旧已审查风险连接的当前ASM显示复制宽度及源图取数偏移必须保持不变；Route35由原10列回退、Route30南偏移抹掉，都会触发失败。
- 该检查已接入 `johto_pilot_migration_audit.py`；新增6项测试（新边、窄接宽、逆向缺失、回退10列、源偏移错误）。它不自动修复内容，也不修改Gold原始数据。

**能力边界：** 此工具是“新连接必须接受人工可视几何审查，否则审计拒绝”的准入门禁，并不是能自动计算全部游戏镜头时序的模拟器。审核者仍须提供Gold接缝源、可视宽度、buffer写入区域、出口碰撞及反向连接的可重复负向测试。今后新增东西时，先把新接缝合同和故障注入加入门禁，而不是在事后被用户截图指出。

## 扩图前的必须检查

1. **资料完整**：Gold原图／属性、成熟NPC参考和旧工具说明缺任何必需项，停止并向用户索取，不允许凭预览推算整张图。
2. **注册一致**：活动地图表、运行时Header、图块／Warp图块指针表、地图名称、音乐、骑车、Fly、Cut/Surf/跳崖、Script Bank和ROMX容量一致。
3. **双向Warp**：每个目的槽、落点、自动步进、方向性门毯，向内与向外两条路径均通过；用户往回走不越界。
4. **四方向接缝**：Gold偏移、源镜像Bank、三行可视buffer、相邻地图边角预览以及精确出口；任何新连接未经登记审查直接失败。
5. **碰撞和图层**：每张新地图确实经过引擎分派；成熟掩码、脚步长草遮挡、骑车／步行、合法门口和未开放门口不得互相矛盾。
6. **交付两阶段**：综合静态审计和故障注入全绿只是开发候选；新ROM链接、最新MAP ROM0≥64B、设备上进入/返回/屏幕滚动/草与围栏的实机测试完成才可转正式验收。

## 使用

在当前 `.290` 工程根目录：

```sh
python tools/johto_active_seam_coverage_gate_291.py --project .
python tools/johto_pilot_migration_audit.py --project . --gold-root /path/to/Gold/pokegold-master
python -m unittest tools.tests.test_johto_active_seam_coverage_gate_291
```

准入测试必须成为以后扩图脚本每次执行的**必跑项**；任何FAIL不得宣称脚本已通过，更不能用增加白名单或删除测试来掩盖。
