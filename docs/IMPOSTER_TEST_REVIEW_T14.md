# RPP「变身者」与独立战斗测试模式：规则、场景、风险审查交接

**审查目标版本**：正式 ROM `IMP-5.62.207`，测试 ROM `TEST-208`（测试菜单修订 T14）。
**源码基线**：用户提供的 T12 项目 ZIP（导出记录中的 HEAD 为 `54b4eb5f00d83eca8ea518b8d8b2ea93320fbc7b`，ZIP 里的源码为含未提交改动的 Worktree）；T13 为其后的菜单重构补丁，T14 是本次对 UI 的修改。**上述 HEAD 只是导出记录，不代表 T14 已 Git 提交。**
**文档用途**：交给独立窗口进行代码审查和补充测试设计。本文区分“实现意图 / 源码可核对事实 / 用户观察 / 尚未验证”，禁止把静态核对当作真实 ROM 编译或实机通过。

> **历史状态说明（T15 收口）**：本文件保留 T14 时点的规则与场景交接记录；后续菜单 BG 状态恢复及用户最终验收状态以 `docs/IMPOSTER_TEST_REVIEW_T15.md` 和 `docs/BATTLE_TEST_BUILD.md` 的 TEST-209 记录为准。

## 1. 功能目标与明确约定

百变怪（`DITTO`）具有类第五世代「变身者 / Imposter」的**固定入场效果**，不建立通用 Ability 特性系统，也不修改全部宝可梦的特性字段。

1. **玩家或敌方首发**：双方准备完成后，百变怪免费尝试变身，首发成功后当回合仍可正常选择复制后的招式。野生百变怪、训练师百变怪与玩家百变怪都在覆盖目标内。
2. **战斗中主动换入**：在真实的入场节点尝试变身；普通换人依旧消耗该方当回合行动，自动变身不再额外占一次攻击。
3. **昏厥后补位**：双方补位都应触发；如果双方同时昏厥，不能对 HP=0 的旧目标执行变身，玩家百变怪应等待新的敌方目标真正装载后再执行一次。
4. **离场 / 再入场**：变身状态随正常换人规则解除；重新上场再次判定。目标单方面换人、打开菜单、进入下一回合都**不应重触发**。
5. **自动失败**：保持未变身的百变怪，保留原始 `Transform` 招式，允许日后主动出招手动变身；失败不额外消耗行动或 Transform PP。
6. **自动成功**：复制与当前项目原有 `TransformEffect_` 一致的战斗临时数据：种类、形态、外观、属性、相关能力值/能力变化、招式、招式身份侧表；临时招式 PP 常规赋 5。**不复制目标当前/最大 HP、不永久覆写 Party 招式**。
7. **原有自定义失败判定必须保留**：变身者走现有 `TransformEffect_`，目标处于 Fly/Dig `Invulnerable` 时拒绝；施术者已变身时拒绝；双方**当前物种 + 运行时地区形态均相同**时拒绝。因此双未变身百变怪默认不互变。当前核心没有显式“目标有替身就拒绝”的分支：**替身不应被臆自改为后世代官方失败规则**。目标已变身等后世代附加限制，不能在未核对源码时宣称已实现。
8. **动画**：战斗动画 ON 时，自动变身调用项目现有 `TransformAnim`，包括正常换图；OFF 时直接重绘。入口动画应保护已保存的动画 ID/type，不更改已选招式，不额外扣 PP；普通手动 Transform 的执行方式维持原状。
9. **训练师换人顺序**：RPP 当前可出现玩家攻击后训练师才换人（原引擎既有决策时序）；但是训练师本次换人**必须占用敌方自己的行动槽，不能随后额外攻击**。不要为了测试变身者而重写正式 ROM 全局换人优先级。
10. **同回合双方换人**：目前受控测试中玩家先换入百变怪、复制**换出前**的敌方卡比兽，随后敌方 AI 行动阶段换成比雕；玩家百变怪既不二次触发，也不变成比雕。若将来改变真实回合换人先后顺序，应单独重新评估这条预期。
11. **联机战**：代码路径共用但联机双机同步、图形时序没有专项设备验收，不得声称已验证。

## 2. 测试模式本身的要求（T14）

- 仅 `make test-red / make test-blue` 构建包含测试 NPC 和夹具；普通 `make red / make blue` 不应包含这些设施。**测试 ROM 必须使用独立 SAV**，测试选择会直接重写当前测试队伍，退出战斗并不恢复队伍。
- 玉虹大厦 1F 的 Pokey NPC（原用户定稿位置 `($00,$0A)`）与其对话时**直接进入** `SELECT TEST`，没有多余的 `Start test? YES/NO`、没有 NPC 二次警告或额外确认。
- 顶层仅两个分类：`SUBSTITUTE TEST`（替身交互测试 3 个）和 `IMPOSTER TEST`（变身者 15 个）。分类中 B 返回顶层，顶层 B 返回地图；**只有最终确认一个实际场景**才可以改测试队伍并启动战斗。中途取消不改队伍。
- `IMPOSTER TEST` 是 5 页、每页 3 项 + `PAGE x/5`；第一次进入该子菜单时光标停 `PAGE`，左右仅在 PAGE 行切页，翻页后仍停 PAGE 行，最左 / 最右页不循环；在 PAGE 行按 A 不启动战斗。`SUBSTITUTE TEST` 与根目录没有 PAGE 行，光标默认第一项。
- 菜单下方固定显示简短测试版本 `TEST-208`，字符直接来自 ROM0 `GameVersionText` 并由 `PlaceString` 绘制，**不用 `TX_RAM wBuffer`**，避免 T13 截图中 `Ver:` 后显示乱码的问题。设置页的版本文本也使用同一公共标签。
- 菜单全程只保留**一个** `SaveScreenTilesToBuffer1` 的原地图备份；所有子菜单 / 翻页只重绘同一菜单区域；真正退出顶层或进入测试战斗之前才恢复原地图。与菜单相关的 `wd730`、`hFlags_0xFFF6` 需要成对恢复，所有 B / A 路径保持堆栈平衡。

## 5. 已有测试反馈与仍不能断言的部分

- 用户曾通过 T10/T11 录像反馈：玩家 / 敌方自动变身、双倒补位、地区形态以及扩展招式出现过预期表现。旧 T10 的 05 曾出现错误的“敌方换人后还可能出招”；T11 在测试构建下把强制换人移动到 TrainerAI 行动槽，源码层面修正了这条时序。
- 用户随后主要做选择性测试，表示未观察到异常；15 `NATIVE AI` 使用模拟器快速存读档等到随机换人，未看出区别：本质上合理，因为 05 与 15 都会执行正常换人动作，**区别是触发来源**。本次反馈不能写成 15 在各 AI 分支、各难度都全面通过。
- T12 增加 Transform 原生动画。用户上传 T12 画面并反馈菜单文字问题：`Ver:` 后乱码、菜单层级需要优化；本次 T14 仅修测试 UI。**T14 尚未 ROM 编译 / 设备实测**，因此不是已验证最终效果。
- 用户表示测试场景已经测过，不想重做十五项；本次只要求核对新增的菜单行为、版本文字和入口/退出。独立审查若发现核心安全缺陷，应再提出**最小复现用例**，而不是笼统要求重跑全部。

## 6. 独立窗口重点审查清单

1. **子菜单返回**：顶层 / 替身 / 变身者各按 B，是否逐级返回？取消是否仍会意外触发 `TestSuite_StartFromNpc` 的建队或战斗？是否破坏 `H_AUTOBGTRANSFERENABLED` / 画面状态？
2. **菜单缓存与栈**：单个 Tilemap 缓冲能否完整覆盖进入、切页、返回、B 取消、A 启动这五条路径？中途是否有其他函数重用相同缓冲？ `hFlags_0xFFF6` 与 `wd730` 是否完全恢复？
3. **版本渲染**：`GameVersionText` 从 ROM0 通过 `PlaceString` 读是否稳定？下方版本与菜单边框是否越界、对图块动画 / 字符延迟造成副作用？正式 ROM 是否仍显示 `IMP-5.62.207`？
4. **选项映射**：5 页 × 3 项的编号是否精确映射 `$40..$4E`？PAGE 左右是否仅在第 4 行生效，边界不循环？首次进入 Imposter 光标是否在 PAGE？返回主类后是否保留分类高亮？
5. **回合状态**：变身者动画是否破坏 `H_WHOSETURN`、`wAnimationID/type`、手动 Transform 的 PP / 回合语义？本方和敌方是否都与 `wBattleMonSpecies2` / `wEnemyMonSpecies2` 的原始身份对应？
6. **半无敌 / 替身**：Fly/Dig 拒绝与替身不拒绝均应以当前源码为准，核对是否有未意识到的命中路径检查差异。
7. **双倒 / 同换**：推迟变身的旗标何时重置？玩家入场后敌方才换人，是否有任何无意二次触发？敌方换人是否稳定消耗行动？
8. **资源与构建**：测试菜单只在 `BATTLE_TEST_BUILD` 中编入吗？实际 Bank / ROMX 空间、两个 ROM 版本的编译链接，需要由用户本地构建确认。测试 SAV 隔离和原地图 NPC（原老太太 / 导师）不得被影响。
9. **未覆盖风险**：联机同步、异常战斗退出/逃跑、菜单快速反复开关、战斗动画关闭与地区形态配色等若无真实测试证据，应列为风险，而非填“已通过”。
