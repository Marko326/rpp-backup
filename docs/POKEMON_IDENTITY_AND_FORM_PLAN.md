# 宝可梦身份与地区形态复用：长期设计备忘（REF-338 基线）

> 状态：**设计待评审 / 未实现**。记录 2026-11-04 讨论结论，避免后续开发重新争论或误把纸面槽位视为已释放。本文不修改 ROM、ASM、存档或编号。主任务入口：根目录 `TODO.md` 顶部。

## 1. 产品目标与不变原则

- 玩家看到的**官方全国图鉴编号、顺序和独立条目**保持不变：关都 #001–#151；目标城都新增 #152–#251。内部合并不是删除玩家可见物种，也不是把尼多朗显示成尼多兰的“地区形态”页面。
- 内部宝可梦身份拟从单字节 `Species` 扩展为 `(Species, Form)`；图鉴身份是独立、永久的 `Dex ID`。一个内部载体可以映射不同官方图鉴编号，而真正的阿罗拉／伽勒尔等地区形态仍归本物种图鉴条目。
- **禁止为凑数量而硬凑**：不同世代御三家、长得像的鸟/鼠/龙、相同属性或相似生态位不算合理合并。优先同阶段进化分支，再考虑确实成对的雌雄/对应物种。跨不同进化阶段不合并。
- **绝不整体重排现有 Species ID**：保留所有尚未回收编号的原值；皮皮 35 就仍是 35。原编号被合并后先保留为旧档别名/保留状态，只有可靠迁移后才能谈重分配，不能直接让新物种覆盖旧编号。
- 新设计不得破坏已有地区形态、旧存档、关都图鉴与进化、PC、战斗/训练师、野生遭遇及已有形态收集状态。不能因 ID 有余量就假定 ROM Bank 有空间。

## 2. 讨论确认的合理合并候选（仅理论回收，不表示已释放）

| 家族/关系 | 内部合并想法 | 理论节省 Species | 备注 |
|---|---|---:|---|
| 尼多兰/尼多朗两条三阶段线 | 同阶段两两配对，6→3 | 3 | 正式图鉴 #029–#034 六条独立；性别、孵蛋、进化数据必须独立 |
| 伊布的八种终阶分支 | 水/雷/火/太阳/月亮/叶/冰/仙子 8→1 | 7 | 伊布自身仍独立；进化条件指向 `(Species,Form)`，需要足够形态标识 |
| 飞腿郎/快拳郎/战舞郎 | 无畏小子三个终阶结果 3→1 | 2 | 技能、图片、名称、进化目标形态独立 |
| 霸王花/美丽花 | 臭臭花两条分支 2→1 | 1 | 叶之石/日之石必须导向不同形态 |
| 蚊香泳士/蚊香蛙皇 | 蚊香君两条分支 2→1 | 1 | 条件进化分歧，别误用相同形态继承 |
| 呆壳兽/呆呆王 | 呆呆兽两条分支 2→1 | 1 | 独立资料和进化结果 |
| 肯泰罗/大奶罐 | 雄牛/雌牛的**自定义对应关系** 2→1 | 1 | 并非官方同一种或进化分支；需要双方性别及繁殖规则 |
| **合计** | **严格候选** | **16** | 仅是规划上限，不是已安全回收的 16 个槽位 |

另外，拉帝亚斯/拉帝欧斯是可讨论但**不默认合并**的雌雄成对物种。其它没有明确关系的物种不强行挂载。第三及后续世代现有物种是否保留/移除，另行做产品取舍，不在未调查引用关系前直接删除。

容量参考：上次清点得到普通物种 208、普通编号保守可用上限 249、空闲 41；第二世代新增 100 中已有 35，缺 65。`41+16=57`、`65-57=8` 只是**理论算术**；不包含额外的 ROM 空间、形态身份记录容量、存档迁移成本，不是可实施性证明。优先保持当前 ID、不做批量平移。

## 3. 必需的架构改造（按依赖顺序）

- [ ] **只读基线审计**：冻结 208 个 Species ID、名称/图像/数据/演化引用；盘点现有地区形态标记、128 个独立形态收集身份槽（此前有 80 条登记）和实际空闲容量；核实当前源码而非沿用旧快照。
- [ ] **身份映射**：建立 `Dex ID ↔ (Species,Form)` 双向表。一个 Dex ID 可以拥有普通/地区形态；多个 Dex ID 可共用底层 Species；判定时不能只看 Species。
- [ ] **独立图鉴显示与收集位**：仍按 #001–#251 排序，逐条独立 Seen/Owned、名称、图像、体型、介绍；地区形态共享官方 Dex ID；合并物种有不同 Dex ID，图鉴页不能被折叠到载体页。
- [ ] **形态专属资料**：名称、属性/种族值、正反图、图标、叫声、升级招式/可学技能、进化分支、性别比例、孵蛋与后代归属、图鉴资料都由真正身份决定；挨个确认旧接口。
- [ ] **进化目标带 Form**：进化条件选择 `(目标Species,目标Form)`，例如臭臭花用两种石头得到霸王花和美丽花；尼多家族阶段间保持性别形态；伊布多条件选择8种结果。
- [ ] **持久存储**：核对捕捉、队伍、PC、育成屋、交换、战斗临时数据、训练师队伍、野怪生成及相关变身/复制路径的形态保存与还原；检查现有 CatchRate 标记冲突和可扩展性。
- [ ] **旧存档迁移协议**：增加可识别的存档版本和单次迁移；包括队伍、盒子、图鉴 Seen/Owned、育成屋、当前战斗上下文等；任何旧 ID 的再分配必须在兼容性验收通过**之后**进行。
- [ ] **ROM/Bank/测试**：核算指针表、图像/技能/进化/名称跨 Bank 引用，Red/Blue/TEST 全新构建和 MAP；ROM0 至少64B 的既定项目要求；旧档继续→保存→读档，以及新旧地区与各类形态的回归。
- [ ] **安全回收台账**：每个候选旧编号分为 `占用中`、`已形态化但旧档保留`、`迁移已验证`、`可以重分配`、`已分配给新物种`；未验证前不进行复用。

## 4. 最小验证顺序（与城都地图开发解耦）

1. **美丽花/霸王花**：相同目标 Species 不同进化结果；独立图鉴 #045/#182 与 PC/保存验证。
2. **尼多家族**：6 个可见图鉴身份 / 3 个内部载体，测试雄雌独立演化、繁殖、#029–#034 顺序和旧存档。
3. **伊布多分支**：8 种终阶共载体，扩展 Form ID/持久标记后测试各种进化条件与多形态显示。
4. **飞腿郎家族、蚊香蛙皇、呆呆王、肯泰罗/大奶罐**：从简单到复杂增量验证。
5. 测试全部通过再讨论回收编号的安全时点，以及第二世代未接入的65只如何分配；**不要求城都地图施工等待此工程完成**。
